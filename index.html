01 el concepto

¿Qué es Google Colab?

Colab (abreviatura de Colaboratory) es un cuaderno interactivo que se abre en el navegador. En vez de instalar Python o R en tu computador, escribes el código en una página web y este se ejecuta en un computador de Google que se te presta temporalmente.

La idea del cuaderno es mezclar, en un mismo documento, bloques de código que se ejecutan y bloques de texto que explican. Vas armando tu análisis paso a paso, viendo el resultado de cada trozo antes de seguir.

Por qué se usa tanto para aprender

  • No instalas nada. Solo necesitas una cuenta de Google y navegador.
  • Trae las librerías más comunes ya listas (pandas, numpy, matplotlib, scikit-learn…).
  • Se guarda solo en tu Google Drive, como un documento más.
  • Se comparte con un link, igual que un Google Doc.
  • Ofrece GPU gratis, útil cuando entrenas modelos.
🔑
La idea clave

Un cuaderno = celdas apiladas. Cada celda se ejecuta por separado, pero todas comparten la misma memoria. Lo que defines en una celda queda disponible en las siguientes.

Entras desde colab.research.google.com y creas un cuaderno nuevo.

03 los dos tipos de celda

Código vs. texto

Un cuaderno se construye combinando estos dos ladrillos. Distinguirlos es lo primero que hay que tener claro.

Celda de código — se ejecuta

[ ] código 
precio = 1990
cantidad = 3
print("Total:", precio * cantidad)

Celda de texto — solo explica

¶ Aa texto (Markdown)
## Resultados Aquí explico **qué encontré** y por qué importa.
Resultados Aquí explico qué encontré y por qué importa.

Arriba: cómo lo escribes en Markdown; abajo de la línea punteada: cómo se ve al ejecutar la celda de texto.

🔀
El orden de ejecución no es el orden visual

Puedes ejecutar las celdas en cualquier orden, y el número [1], [2]… a la izquierda te dice en qué orden las corriste. Esto es la causa #1 de confusión al empezar (más sobre esto en «Errores comunes»).

04 hacer correr el código

Ejecutar celdas

Hay tres formas de ejecutar la celda en la que estás parado:

  • Presionar el botón ▶ a la izquierda de la celda.
  • Shift + Enter — ejecuta y salta a la celda siguiente.
  • Ctrl + Enter — ejecuta y se queda en la misma celda.

Prueba con esta. Recuerda: la variable que definimos antes queda en memoria, así que las celdas se pueden apoyar unas en otras.

[ ] código 
for i in range(1, 4):
    print(f"Vuelta número {i}")
▶
La última línea se muestra sola

En un cuaderno, si la última línea de una celda es un valor (por ejemplo df.head() o simplemente 2 + 2), Colab imprime su resultado automáticamente, sin necesidad de print().

05 el paso que a todos confunde

Importar e instalar librerías

Una librería es código que otras personas ya escribieron y que tú reutilizas. Hay dos verbos que se confunden mucho al principio:

  • Instalar = descargar la librería al entorno. Se hace una vez por sesión, y solo si no viene preinstalada.
  • Importar = cargarla en tu código para poder usarla. Se hace siempre, en cada cuaderno.

La mayoría de las librerías de datos ya vienen instaladas en Colab. Con esas, basta con importarlas:

[ ] Python 
import pandas as pd      # ya viene instalada
import numpy as np

df = pd.DataFrame({"ciudad": ["Santiago", "Valpo"],
                   "ventas": [120, 85]})
df

¿Y si necesitas una que no viene preinstalada? La instalas con !pip install. El signo ! al inicio le dice a Colab «esto no es Python, es un comando del sistema».

[ ] Python 
!pip install yfinance -q   # instalar (una vez por sesión)
import yfinance as yf      # importar para usarla

En un cuaderno con entorno de R, importar se hace con library(). Muchos paquetes base ya están disponibles:

[ ] R 
df <- data.frame(
  ciudad = c("Santiago", "Valpo"),
  ventas = c(120, 85)
)
head(df)

Para un paquete que no está, se instala con install.packages() y luego se carga con library():

[ ] R 
install.packages("ggplot2")   # instalar (una vez)
library(ggplot2)             # cargar para usar
🧩
Ojo con el operador de asignación

En R lo habitual es <- (no =) para asignar valores. Ambos funcionan, pero <- es la convención.

06 traer tus datos

Subir archivos y conectar Drive

Tu cuaderno empieza vacío: no ve los archivos de tu computador. Hay dos formas de darle datos.

Opción rápida — subir un archivo suelto

Sirve para probar algo puntual. Cuidado: lo que subes así se borra cuando el entorno se reinicia.

[ ] Python 
from google.colab import files
subidos = files.upload()   # abre un botón para elegir el archivo

Opción recomendada — montar Google Drive

Conecta tu Drive al cuaderno. Así tus archivos persisten y trabajas siempre sobre los mismos datos.

[ ] Python 
from google.colab import drive
drive.mount("/content/drive")

# ahora tus archivos están dentro de esa ruta:
import pandas as pd
df = pd.read_csv("/content/drive/MyDrive/ventas.csv")
⚠️
Todo es temporal salvo Drive

El entorno de Colab se borra al desconectarse (por inactividad o al cerrar). Las variables, los archivos subidos y las librerías instaladas se pierden. Tus datos se conservan solo si están en Drive; tu código, porque el cuaderno se guarda en Drive automáticamente.

07 el lenguaje de la estadística

Usar R en Colab

Colab es de Python por defecto, pero corre R perfectamente. Tienes dos caminos, según lo que necesites.

Camino A — un cuaderno 100% en R

Si todo tu trabajo es en R, abre un cuaderno con entorno de R desde el principio. La forma directa es entrar a esta dirección, que crea un cuaderno nuevo ya configurado en R:

↗ dirección web · abre R directo 
https://colab.research.google.com/#create=true&language=r

Ahí cada celda es de R directamente — usas library(), install.packages() y <- sin nada extra.

Camino B — R dentro de un cuaderno de Python

Si trabajas en Python pero quieres una celda puntual en R, activa el «puente» rpy2 y marca la celda con %%R arriba:

[ ] Python → R 
%load_ext rpy2.ipython   # activar el puente (una vez)
[ ] celda de R 
%%R
x <- c(4, 8, 15, 16, 23, 42)
summary(x)
🧭
¿Cuál elijo?

Todo en R → Camino A, más limpio. Mezcla puntual (traer un dato desde Python y graficarlo con R, por ejemplo) → Camino B.

09 cuando algo falla

Errores comunes al empezar

Ninguno es grave. Casi todos vienen de la misma idea: las celdas comparten memoria y el orden en que las corres importa.

NameError «name '…' is not defined» ＋

Estás usando algo (una variable, un df) que definiste en otra celda que no ejecutaste todavía, o que se borró al reiniciar. Vuelve arriba y ejecuta las celdas en orden.

Truco: Entorno de ejecución → Ejecutar todas corre el cuaderno completo de principio a fin.

ModuleNotFoundError «No module named '…'» ＋

La librería no está instalada en este entorno. Instálala primero con !pip install nombre (Python) o install.packages("nombre") (R), y recién después impórtala.

Se desconectó y «perdí todo» ＋

Por inactividad, Colab desconecta el entorno y borra su memoria: variables, archivos subidos y librerías instaladas. Tu código no se pierde (el cuaderno se guarda en Drive). Solo reconéctate y vuelve a ejecutar las celdas.

FileNotFoundError al leer un archivo ＋

La ruta no existe en el entorno. Si el archivo está en Drive, primero móntalo (drive.mount(...)) y usa la ruta completa, del tipo /content/drive/MyDrive/archivo.csv. Evita rutas de tu computador como C:\Users\...: esas no existen en Colab.

El resultado no cambió aunque edité el código ＋

Editar una celda no la ejecuta. Tienes que volver a correrla (▶ o Shift+Enter) para que el cambio tenga efecto.

10 comprobar lo aprendido

Mini-quiz

Tres preguntas rápidas. Elige una opción para ver si acertaste.

1. Necesitas la librería seaborn y al importarla sale ModuleNotFoundError. ¿Qué haces?
La librería no está en este entorno: se instala con !pip install y después se importa. Muchas ya vienen listas, pero cuando no, ese es el paso.
2. ¿Qué significa que Colab «se desconectó por inactividad»?
El código vive en tu cuaderno (guardado en Drive). Lo que se pierde es la memoria del entorno: variables, archivos subidos e instalaciones. Reconectas y ejecutas de nuevo.
3. Trabajas en Python y quieres una sola celda en R. ¿Qué usas?
Con %load_ext rpy2.ipython activas el puente, y cualquier celda que empiece con %%R se ejecuta como R dentro del mismo cuaderno de Python.
